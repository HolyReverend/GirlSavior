# Unreal project context

- Engine version confirmed through live Editor identity on 2026-11-07: installed Unreal Engine 5.8.4. [GirlSavior.uproject](../GirlSavior/GirlSavior.uproject) records `EngineAssociation` as `5.8`.
- The primary module is `GirlSavior` (`Runtime`). Its [Build.cs](../GirlSavior/Source/GirlSavior/GirlSavior.Build.cs) lists `Core`, `CoreUObject`, `Engine`, `InputCore`, and `EnhancedInput` as public dependencies. The targets are `GirlSavior` (Game) and `GirlSaviorEditor` (Editor).
- [DefaultInput.ini](../GirlSavior/Config/DefaultInput.ini) selects Enhanced Input. [DefaultEngine.ini](../GirlSavior/Config/DefaultEngine.ini) sets both Editor Startup Map and Game Default Map to `/Game/Maps/Demo.Demo`.
- [Prototype 1 Stage 0](../Docs/Technical/Prototype%231/Stage00-ProjectPreparation.md) is technically verified on 2026-11-07. `Demo` contains a 2,400 × 2,400 cm floor with its top at Z = 0, simple blocking collision, basic lighting and one PlayerStart at (0, 0, 92). At the end of Stage 0 it used stock GameModeBase and DefaultPawn; Stage 1 subsequently replaced them with the prototype classes listed below.
- The project enables `ModelingToolsEditorMode` and `PinWright` for the Editor target. For live editor work, read the [PinWright guide](PinWright.md).

- [Prototype 1 Stage 1](../Docs/Technical/Prototype%231/Stage01-CharacterMovement.md) is implemented, technically verified and accepted by the user after manual testing on 2026-11-07. Demo overrides BP_PrototypeGameMode with BP_PrototypeCharacter and BP_PrototypePlayerController. Native feature folders: Core/, Characters/, Camera/. Input assets: Input/Actions/IA_Move and Input/IMC_Gameplay. Ground speed is 500 cm/s; response defaults 0.10 s moving and 0.08 s stopping. Rigid camera: 35° down / 45° yaw, FOV 45°, distance 1600 cm. Stage 2 extends this baseline as described below. Stage 1 documents the editor-only movement capture/evaluator.
- [Prototype 1 Stage 2](../Docs/Technical/Prototype%231/Stage02-GameplayCamera.md) is implemented, technically verified and accepted by the user after the manual route on 2026-11-07 («Пройдено — всё работает»). BP_PrototypePlayerController selects BP_PrototypeCameraManager. Camera defaults: 45° horizontal FOV / 1600 cm, −35° pitch / 45° yaw, 0.20 s settle, 20% screen margin, 0.15 s foreground fade with 20% remaining coverage. Demo adds two authored room bounds, one positional doorway transition, a foreground blocker and a 0.8 s warning fixture while preserving the Stage 1 lane. CameraOcclusion uses ECC_GameTraceChannel1, default Ignore; tagged upper meshes overlap. Call RequestFollowSnap after same-pawn teleports. Stage 3 aim consumes the final camera cache in TG_PostUpdateWork using absolute viewport pixels and the constrained view rect. See Stage 2 for reproducible probes and evidence.
- [Prototype 1 Stage 3](../Docs/Technical/Prototype%231/Stage03-CharacterAiming.md) implements native body-plane mouse aiming in `UGirlSaviorAimComponent`, owned by `AGirlSaviorCharacter`. It ticks on the game thread in `TG_PostUpdateWork`, samples absolute viewport pixels against the constrained rectangle, and keeps direction/hold across interruptions. Editable hold defaults are 1% enter / 1.5% exit of view height. `GetAimDirection()` is the world XY unit facing; `IsCursorInsideGameView()` is a transient sample. Firing must also check `AGirlSaviorPlayerController::CanUseGameplayInput()` live and make aim its tick prerequisite. `SetGameplayInputAvailable(false)` suspends full gameplay control; movement-only locks do not suspend aim. GameAndUI uses CaptureDuringMouseDown, visible cursor and DoNotLock. Closed-editor build, deterministic aiming probes, live current-frame/pause/suspension checks and movement/camera regressions pass. Stage 3 was accepted on 2026-11-07 after the user reported «Пройдено — всё работает» for the supplied manual route. `GirlSavior.AimDebug 1` draws a temporary facing arrow; `GirlSavior.TestAim <width> <height>` probes synthetic pixel rectangles with the live final camera matrix.
