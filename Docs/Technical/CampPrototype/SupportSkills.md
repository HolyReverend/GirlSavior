# Heroine and support skill data

Each heroine has a Data Asset with her profile and skill references. Each skill has a separate Data Asset with card content and a list of editable mechanic definitions. A mechanic definition describes one reusable behavior. Its runtime instance owns the live values and subscriptions for one expedition. | `UGirlSaviorSupportAbilityDefinition` in `Support/GirlSaviorSupportAbilityDefinition.*` | `UDataAsset` with `FName AbilityId`, `FText DisplayName`, `FText Description` for activation and purpose, `TObjectPtr<UTexture2D> Icon`, and `UPROPERTY(EditAnywhere, Instanced) TArray<TObjectPtr<UGirlSaviorSupportEffectDefinition>> Effects`. | `UGirlSaviorSupportEffectDefinition` in `Support/GirlSaviorSupportEffectDefinition.*` | Abstract native `UObject` with `EditInlineNew` and `DefaultToInstanced`. | `UGirlSaviorSupportEffectRuntime` and `UGirlSaviorSupportRun` in `Support/GirlSaviorSupportRun.*` | Create one concrete runtime per selected effect with `NewObject`, outered to the support run. The encounter holds the run in a transient `UPROPERTY`, and the run holds its effects the same way. The effect factory copies validated tuning to runtime values. Implement attach/detach and narrowly typed event hooks as needed. Keep actor references weak and clean up delegates, timers and temporary modifiers in teardown. |
| `UGirlSaviorCampDefinition` in `Camp/GirlSaviorCampDefinition.*` | `UDataAsset` with `TArray<TObjectPtr<UGirlSaviorHeroineDefinition>> Roster`, ordered `TArray<FName> AvailableAbilityIds`, `FName MissionId`, `FText MissionName`, `FText MissionDescription`, and `TSoftObjectPtr<UWorld> ExpeditionMap` and `CampMap`. Use the roster to resolve each offer to one heroine and one skill. This asset is the Camp fixture's catalog and mission source. |

Use the existing `UDataAsset` pattern with hard references for the small authored roster, skills, and icons. The two level references are soft and point to explicitly cooked maps. The map table provides the root asset reference. Keep gameplay values and presentation fields designer-editable and document each parameter in Russian in its owning schema. Use `FText` for player-facing strings and keep object names, stable IDs and localized labels independent. ### Validation and extension

- Require one populated roster entry per heroine ID and one owning heroine for each offered ability ID. Reject null references, duplicate IDs across the roster, empty IDs or display text, missing offered icons, empty or null effect entries, and invalid effect values. Validate all offered skills, plus ID integrity and ownership across the roster. For this fixture require three offers and one offer per heroine. Additional owned skills appear when a later availability rule exposes them.
- Reuse pure validators from editor `IsDataValid` overrides under `WITH_EDITOR` and from native preparation. In Camp, check the full catalog, mission, required soft map refs and distinct package paths. Resolve the two draft IDs through the catalog. At both ends, check that the resolved ability references match the payload IDs and pass ability and pair validation. The destination trusts Camp's accepted ownership and availability checks through the matching session claim. Editor validation reports the asset path and field. Runtime returns a narrow status and logs details. The same native validation result drives launch eligibility and actual dispatch.
- Each v1 mechanic has a distinct `EffectKey`. Reject repeated keys in a single ability or across a selected pair until that mechanic defines a stacking rule. Validate all three catalog pairs during content validation so every advertised pair works. Check finite ranges independently of editor clamps. Each concrete mechanic defines its supported values.
- Add an additional skill by creating an asset, assigning it to a heroine, and adding the offer through the selection source. To compose an ability, add another supported effect to its `Effects` array and configure it. To add a new kind of behavior, create a native definition and its matching runtime hook. The Camp widget and session handoff continue to consume the same ability schema. Use mechanic-specific hooks and a native factory within each concrete definition, keeping ability IDs out of combat switches.

## Editor authoring

1. In `Content/Data/DataAssets/Camp/`, create `DA_CampPrototype` and `DA_Heroine_Liora`, `DA_Heroine_Ida`, `DA_Heroine_Saira` with **Miscellaneous → Data Asset** and the appropriate native class. Set heroine IDs `Liora`, `Ida`, `Saira`. Use the heroine files for name, brief profile and support role. The fixture uses the same asset for the scene actor, profile panel, and skill card owner.
2. Create the three `DA_Support_*` assets from the native skill definition class. Set their IDs, display names, descriptions, and placeholder texture icons. Add the specified concrete mechanic in each asset's `Effects` array in Details. Keep the three editable numeric configurations below in those inline definitions.
3. Assign each skill to its owner's `Abilities`. Set the Camp roster to the three heroines and `AvailableAbilityIds` in Liora, Ida, Saira order. Use `CombatPrototypeRoute` as the mission ID and `Боевой маршрут` as its title. Assign `/Game/Maps/TestMaps/CombatPrototypeRoute` and `/Game/Maps/TestMaps/CampPrototype` via the asset picker once both maps exist. Run complete asset validation after assigning both maps.
4. Save, reopen, and inspect the three inline definitions after editor reload. Confirm that changing an asset parameter alters its rendered card detail and that the corresponding runtime test follows the edited value. Restore the baseline values before acceptance.

## First three skills

| Heroine | Asset and stable ID | Mechanic parameters |
| --- | --- | --- |
| [Лиора](../../GameDesign/Mechanics/Heroines/Liora.md) | `DA_Support_StaticTrace`, `StaticTrace`, `Статический след` | `WeaponHitSlow` with `SlowFraction = 0.10` in `(0, 1)` and `DurationSeconds = 1.5` above zero. Successful direct hero weapon damage refreshes slowing on a living enemy. |
| [Ида](../../GameDesign/Mechanics/Heroines/Ida.md) | `DA_Support_MechanismOverdrive`, `MechanismOverdrive`, `Разгон механизма` | `WeaponRate` with `RateMultiplier = 1.06` at least `1.0`. The pistol launches at the configured base rate times this multiplier. |
| [Сайра](../../GameDesign/Mechanics/Heroines/Saira.md) | `DA_Support_TravelersBarrier`, `TravelersBarrier`, `Барьер путника` | `RechargeBarrier` with `HealthFraction = 0.08` in `(0, 1]` and `RechargeDelaySeconds = 6.0` above zero. Start with a full barrier based on maximum health. Refill after the configured time without damage. |

Combat tuning, enemy definitions and heroine catalog assets remain read-only during play. Runtime state belongs to the current world. For future save slots, start from a persistence model keyed by stable heroine and skill IDs. For later progression, resolve available offers and purchased ranks before forming the launch payload, then keep that expedition's runtime configuration fixed.
