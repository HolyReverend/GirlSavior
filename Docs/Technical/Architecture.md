# Current project architecture

The project targets Unreal Engine 5.9 Preview (Epic Games Launcher, verified build 5.9.0 CL 60738873). Demo, the combat fixtures, and the wave route share the existing controls and camera.

## Entry points and assets

`Config/DefaultEngine.ini` opens `/Game/Maps/Demo` for both editor and game. The map overrides the GameMode.

```text
Demo → BP_PrototypeGameMode
       ├─ BP_PrototypeCharacter → custom movement + AimComponent + FireComponent
       └─ BP_PrototypePlayerController
          ├─ IMC_Gameplay → IA_Move
          └─ BP_PrototypeCameraManager → DA_CameraManager
```

Blueprints under `Content/Blueprints/Core/` and `Characters/` configure the matching native classes. Input lives in `Content/Input/`. `Content/Data/DataAssets/DA_CameraManager` is a `UGirlSaviorCameraSettings` asset holding shared camera tuning. `Demo` also places native Room Bounds, a foreground occluder, a warning fixture, and the Stage 4 target/wall/safe-area lane. `BP_TestProjectile` provides a collision-free sphere visual and Blueprint impact cues; `BP_TestTarget` composes a blocking mesh and damage receiver; `BP_PrototypeSafeArea` adds a floor marker to the native trigger.

`BP_PrototypeCharacter` assigns `Content/Data/DataAssets/Combat/DA_PrototypeDash` to its movement component.

`/Game/Maps/TestMaps/CombatPrototype` uses `BP_CombatPrototypeGameMode` and `BP_CombatPrototypeCharacter`, which inherit the Demo controls and camera. The combat Blueprint assigns `DA_HeroCombatPrototype`, `DA_CombatPistol`, and `BP_CombatPistolProjectile`. The safe pocket opens onto the Pursuer arena, with a health target and the exit. Three rooms through the north doorway contain a Shooter, a Charger, and one of each together. The five enemies reference explicit fixture bounds and role Data Assets. The Shooter definition supplies `BP_EnemyProjectile`. Saved navmesh connects the four rooms.

`/Game/Maps/TestMaps/CombatPrototypeRoute` uses the same pawn and combat assets. It starts in the safe pocket and continues through the Pursuer, Shooter, Charger, Quiet, and Mixed rooms to the exit. The encounter assigns `DA_CombatWaveSettings`, the five `DA_WaveProfile_*` assets through room references, and the three CP2 enemy classes as the spawn roster. Entrances supply exact capsule-center transforms. The route stores baked open-floor navigation with dynamic modifiers for the test door. `BP_CombatFeedbackPresenter` connects the encounter to the dark fixture, Torch, audio, `BP_CombatWarning`, `WBP_CombatHUD`, and `WBP_CombatOutcome`.

`/Game/Maps/TestMaps/CampPrototype` uses `BP_CampPrototypeGameMode`, the shared `BP_PrototypeCharacter` and `BP_PrototypeCameraManager`, and `BP_CampPlayerController` with `IMC_Camp`. The walkable floor contains the expedition table, three heroine placeholders, a campfire, workshop and shelter markers, and one camera room bounds actor. The table assigns `/Game/Data/DataAssets/Camp/DA_CampPrototype`. [Camp scene](CampPrototype/CampScene.md)

`DA_CampPrototype` owns the ordered offers and test mission. Its roster references `DA_Heroine_Liora`, `DA_Heroine_Ida`, and `DA_Heroine_Saira`, each with a single `DA_Support_*` card asset. Each card holds an inline typed effect and an icon under `/Game/Art/Textures/Camp/`. The two soft world references point at `CampPrototype` and `CombatPrototypeRoute`. [Support skills](CampPrototype/SupportSkills.md)

## Integration contracts

- `CanUseGameplayInput()` is the live gameplay gate. Full suspension uses `SetGameplayInputAvailable(false)`. Movement-only locks leave aiming available. Mouse input uses GameAndUI with CaptureDuringMouseDown, a visible cursor, and DoNotLock.
- Aim ticks in `TG_PostUpdateWork` after camera evaluation and uses absolute viewport pixels with the constrained view rectangle. Consumers use `GetAimDirection()`. Fire ticks after aim, rechecks the gameplay gate, combat permission, and cursor inclusion, and cancels the series on failure.
- Fire uses one configurable mouse button (default LMB) routed through InputKey edges. A ready tap survives release until the firing tick; cooldown taps do not queue. The double game-time deadline survives cancellation, pause, and rate changes. Successful launches use actual shot time plus 1 / ShotsPerSecond (initially 4). New presses are required after cancellation.
- `SetSafeAreaActive` tracks overlapping zones and cancels fire and dash on entry while walking remains available. Possession inside a zone synchronizes both registries. `SetFireAllowed` independently controls firing.
- Dash consumes a fresh Left Shift edge after Enhanced Input resolves the current WASD direction. The movement component snapshots speed and deadlines and commits short grounded capsule sweeps. The shared damage receiver queries `IsDashProtected()` at contact and blocks direct projectile, melee, and charge damage during the protection window. Area and floor damage use the usual resistance, barrier, and health calculation.
- `PrototypeProjectile` and `EnemyProjectile` are object channels 2 and 3. Hero and enemy capsules block the opposing projectile channel in combat. The Demo projectile keeps its Pawn response. `CombatOccluder` is trace channel 4 for authored blockers and the safe boundary.
- The encounter activates when the hero leaves the safe pocket and reaches the first room. Terminal transitions close gameplay input and clear pending threats after the current dispatch. The outcome panel displays the lethal cause and reloads the current map on retry.
- Shooter and Charger reserve the encounter's dangerous slot only after a visible warning is possible. Only the matching attack ID and holder can transfer or release it. When a Shooter launches, the projectile takes ownership before it moves. Placed enemies only engage a hero within their assigned fixture bounds.
- Wave-enabled encounters count living and reserved enemies across all rooms. A wave commit uses current game time and the current constrained camera view. The hero can cross ordinary rooms with enemies alive. Door state blocks paths immediately while navigation updates its tiles. The protected pocket cancels pending reinforcements and holds enemies outside.
- The route presenter binds target feedback to the committed damage result and projectile geometry feedback to the projectile stop. A death cancels attached threats before presentation. A detached shot keeps its own flight visual, attack slot, and source label until completion.
- Camera tuning belongs in `DA_CameraManager`. After same-pawn teleports, call `RequestFollowSnap()`.
- Camp uses the shared camera and movement. Its controller denies fire and dash, gives focused modals UI-only input, and restores the shared game-and-UI mode when a panel closes. The world continues ticking while a modal is open.
- Camp's `ValidateCatalog` checks the mission and offers. Editor validation and `ResolveLaunchPair` require two distinct saved world references. The expedition session dispatches absolute travel with a single `CampRunId`, commits the ordered pair after successful encounter setup, and clears the active run on return. The remembered pair seeds the next table visit in the same game instance.
- A Camp-origin route binds support before publishing the hero. Liora slows only on a positive, nonlethal hero pistol hit on a registered enemy. Ida multiplies the rate for future shot deadlines. Saira adds a separate barrier pool that absorbs first and refills on a game-time timer. Terminal encounters close support dispatch immediately and detach after the current damage result reaches presentation.
- Camp-origin outcomes use `В лагерь`, including recoverable launch failures with a trusted Camp reference. Direct starts retain `Повторить`. The packaging map list includes Demo, both combat fixtures, and Camp.
- CAMP 4 verified the table, route exit, Camp return and remembered pair in a Win64 Development package. `Demo` is the default map. The Camp map can be passed as a launch argument. The [Camp expedition probe](../../GirlSavior/Source/GirlSavior/Camp/GirlSaviorCampExpeditionProbe.cpp) compiles for Editor and Development so the same command can exercise travel in PIE and in a Development game. [Build and test evidence](CampPrototype/Acceptance.md)
- Room framing uses room footprint geometry and `WallInset`. Side gaps within the inset can join across overlapping sides. Room authoring supports yaw rotation and positive scale with world-up orientation.
- `CameraOcclusion` is `ECC_GameTraceChannel1`, default Ignore, configured in `Config/DefaultEngine.ini`. Fadeable components overlap it, carry `CameraFade`, and use custom primitive data slot 0 in the prototype fade material. Gameplay blocking remains on separate geometry.

## Working requirements

- Use MSVC 14.50.35723 or later in the 14.50 series for the Win64 build. UE 5.9 Preview rejects MSVC 14.51. Visual Studio 2026 lists the compatible compiler under **Individual components** as **MSVC Build Tools v14.50 for x64/x86**.
- The Game and Editor targets both use build settings V8. The installed engine checks the Editor target receipt during interactive startup. After an engine update, rebuild the Editor target so the project module build ID matches the installed editor. The Editor target includes the project automation tests.
- The descriptor enables GeometryProcessing for runtime room geometry. The editor uses Epic's ModelContextProtocol with the Editor toolset, which includes built-in editor Python, plus Blueprint, Automation Test, and Console toolsets. Read the [Unreal MCP guide](../../Codex/UnrealMCP.md) for live editor work and confirm project identity first.
- Use the [documentation index](../README.md) when you need to locate a feature's detailed stage or design document. Match checks to the affected system and record what was actually verified.
